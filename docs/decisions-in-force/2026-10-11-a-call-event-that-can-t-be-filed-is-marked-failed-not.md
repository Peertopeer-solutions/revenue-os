- 2026-10-11 · **A call event that can't be filed is marked failed, not retried; only the database's own trouble is retried** (services/worker/src/vapi/process.ts, `eventsFault`): each event of a company's batch is filed inside its own savepoint. The database's own trouble (a lost connection, a deadlock or serialization failure, no resources, a cancelled or timed-out statement, a system or internal error, a lock wait that timed out: error classes 08, 40, 53, 57, 58 and XX, and 55P03) fails the whole job, marks nothing failed, and pg-boss runs it again. Any other error fails the same way on every run (a timestamp that names no time, a broken key, a call id too long for its key, an error of our own code), so it undoes that event alone and stores status failed with the error's message, and the company's other events go through. Setting a failed event back to received makes the next job file it again.
