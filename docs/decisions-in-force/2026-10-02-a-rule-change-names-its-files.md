- 2026-10-02 · **A rule change names its files**: a `Rule change:` line in the PR body, and a line the PR adds to STATE.md → Rule changes, cover a changed rule file when they name its path, its file name or the folder it sits in (with its "/"), each as a whole word; a line in an HTML comment or a code block, which GitHub doesn't show, counts for nothing; Rule changes only grows, so a change that removes or rewrites a record is refused; the judge reads every file name whole and ignores the repository's .gitattributes, so no name or attribute hides a change; `bun run gate pr` checks both, reading the body from PR_BODY and the number from PR_NUMBER, and `rules-from-main` runs it with `--head` on the pull request's commits, fetched as data without a login while the repository is public, and only on the commit the event names (a later push gets its own run).
