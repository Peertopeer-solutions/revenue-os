- 2026-10-02 · **Staging migrations have their own workflow, started when ci finishes on main** (.github/workflows/staging-migrations.yml, `workflow_run`), not a job in deploy.yml (which starts on the push, before `checks` finishes) or in ci.yml (which cancels a superseded run, so a push to the database could stop half-way, and also runs for pull requests). `workflow_run` always runs main's copy of the file. Besides ci's result, it asks GitHub whether the `checks` check itself passed on that commit, as reported by GitHub Actions, because a skipped `checks` still lets ci's run pass and anyone can post a check of that name. A hand run (`workflow_dispatch`, main only) asks the same. The job that holds the cloud secrets installs nothing: it runs bun, the Supabase CLI and scripts/staging-migrations.ts, which fails the run rather than skipping when it can't read `supabase migration list` or the cloud has a migration the commit doesn't.
