- 2026-10-03 · **A new migration's test is found by name, in code**: a test file is a database test when its code, comments taken out, connects (withOrg, a pg Pool or Client, createPool, testCompanies, LOCAL_DB_URL or DATABASE_URL), and a cross-company denial test when it also runs through withOrg and expects nothing back or a refusal; each table the migration creates must be named in the code of a line the change adds to a denial test, and each function, procedure, view, type, sequence or column it adds (or, when it adds none of those, each table it alters, inserts into, or puts an index, policy or trigger on) in the code of a line the change adds to a database test; a migration with nothing to name needs a database test added or edited in the same change.
