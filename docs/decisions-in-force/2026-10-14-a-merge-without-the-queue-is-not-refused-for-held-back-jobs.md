- 2026-10-14 · **A merge without the merge queue is not refused for the jobs held back from pull requests** ([#179](https://github.com/Peertopeer-solutions/revenue-os/pull/179)): without the queue a pull request lands on its own `checks`, which ran only the quick checks, so the four-runs-at-once test first runs on main, after it lands, and so does the whole suite when the Mac's gate ran without Docker (a pass the merge check accepts, which skips the database tests). Refusing such merges would also break Slice 0's proof, whose merge steps show a merge with no queue going through. The queue is on; switching it off is Devesh's call. CI's pull-request runs are limited to pull requests into main, whose head is never one of main's own commits, so a pull request's `checks`, run with the suite held back, never stands on a commit of main that the staging hand run trusts
