- 2026-10-03 · **A stop answers for any commit main does not hold, however the checkout got there**: a checkout whose latest commit is not on origin/main is judged whenever its code changed since the session last accepted it, so a switch, reset or fast-forward to someone else's commit is judged as the session's own; a worktree new to the session on a branch it accepted elsewhere (one it removed and added again, or moved) is judged from what it accepted on that branch, unless another session worked there last; a session reads a pull request in a worktree of its own (`git worktree add --detach`), which it finds as it is once one of its commands runs there (a stop in a folder the session never noted judges that checkout whole, as before); a checkout with no origin/main holds no main commits; a switch back to a branch already judged is judged again, from the checks' and the verifier's records for that exact code. This replaces the reflog test (a commit counted only when the session made it in that checkout). Work set aside by switching the checkout to main before the stop is left to the merge check.
