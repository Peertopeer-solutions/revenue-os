- 2026-10-13 · **How the merge queue's builds are judged** ([#169](https://github.com/Peertopeer-solutions/revenue-os/pull/169)): the merge check asks GitHub, at each merge, whether main's rules hold a merge queue, and refuses on an answer it can't read; in the queue's build, CI's secret scan reads the commits since the one the queue built on, and its done rules, tests proven and break check judge the change since main (this pull request with those queued ahead of it, each of which passed them alone); and `rules-from-main` reads the queued pull request's number from the queue's branch name and its head and body from GitHub with the job's read-only token (`pull-requests: read`), then judges them with main's copy of the rules exactly as on the pull request; GitHub runs the queued commit's copy of rules-from-main.yml there, a copy main's copy already judged on that pull request.
