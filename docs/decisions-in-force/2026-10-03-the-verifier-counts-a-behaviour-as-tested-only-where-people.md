- 2026-10-03 · **The verifier counts a behaviour as tested only where people meet it**: an API test through the worker's routes, a browser test, or a job's or webhook's own entry point; a test of the database alone never counts, and each standard edge case that can happen (another company, a duplicate, empty input, a failure, a retry) needs its own test, or it rules FAIL naming the test to add. It reads each test and leaves running it to its `bun run gate`, which runs every test under the shared lock on a fresh console build, and it checks written data against the reader's schema on the local stack only, never with a real provider.
