- 2026-10-02 · **A migration on main is judged by its content and file name** (scripts/done-gate/migrations.ts, in `bun run gate pr`): a migration is a `.sql` file directly in supabase/migrations/, as the Supabase CLI reads them; one main had where the branch left it may not change content (a mode change alone is not a change; a link swapped in is) or disappear (a rename counts as a deletion); a new one may not share its number, read as a person does (2 is 002), with any other migration in the branch's own code, which main's ruleset keeps caught up with main, and its file must sort after main's newest, so the cloud test database, which gets it last, runs migrations in the same order as every local database and test; a file in a folder spelled like supabase/migrations/ in another letter case is refused, because a Mac reads it as a migration and Linux doesn't.
