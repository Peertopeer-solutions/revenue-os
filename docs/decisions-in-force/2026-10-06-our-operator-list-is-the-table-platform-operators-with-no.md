- 2026-10-06 · **Our operator list is the table platform_operators, with no org_id** (migration 018): it lists our own people, who may create a company, not any company's data, so hard rail 3's org_id rule does not apply to it. Row-level security is on with no policy and every API role's rights are taken back; the worker asks only `app.is_platform_operator(user)`, which answers yes or no and which only app_service may call. Named so because "operator" is already a role inside a company (app.org_role). Rows are added by hand: the local seed adds the dev login; on the test server Devesh adds people in the SQL editor.
