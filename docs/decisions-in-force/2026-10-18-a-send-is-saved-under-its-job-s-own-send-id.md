- 2026-10-18 · **A send is saved under its job's own send id** ([#189](https://github.com/Peertopeer-solutions/revenue-os/pull/189)): the scheduler gives every job it queues a random send id, which every delivery and retry of that job carries (a job queued without one gets pg-boss's own id for it); the worker saves the job's call or message in the sends table (migration 021) under `<job kind>:<run id>:<send id>`, unique per company, before it calls the provider. So the same job never sends twice, while a later visit to the same step is a new job with a new id and does send. A run parked on a call names that call job's send id in its state, so a late run of an older call job does nothing to it.
